# Diagram Design Principles

## 適用範囲

説明用の図解とその計画に適用する Context である。情報伝達、反復する概念の共通定義、構図の可読性の判断基準を提供する。
活動の目的・成果物・作業順序・完了条件・提出形式は定めない。計画の作成や最終成果の生成を開始する指示ではなく、作成・変更・レビューに共通して使う規則である。
段落単位の扱い、生成ツール、保存先、画風・配色・書体は対象外である。

## 不変条件

### 情報伝達

- 単純図形、ラベル、配置、矢印、包含などの関係表現が、主題を伝える主体になっている。
- 主題を担う各図形には、それが表すモノ・コトを示す短いラベルが付いている。ラベルは複数単語でもよいが、文章ではない。
- 絵・アイコンは概念の理解と識別を速める補助要素として、対応する図形の内側または直近に置かれている。それだけに概念や関係の意味を担わせていない。意味を担うのはあくまでラベルである。
- 厳密さや網羅性より直感的な理解を優先し、その理解に不要な説明や冗長な情報を含まない。ただし、情報の簡略化によって、主題、主要な関係、変化、結果が欠落または変質していない。
- 要旨を伝えるために必要な要素だけで構成され、文字と図は、主題の理解に必要な情報を保てる範囲で少なく大きい。
- 説明用の短文は、図形内、矢印・接続線上、または対象へ接続されたコールアウトとして図解の一部になっている。図解要素と対応しない説明文、見出し、キャプションは単独で存在していない。
- UI、看板、コードなど、図解対象そのものに含まれる文字は、主題や対象を識別するために必要な部分が残されている。表示する文字の内容と言語は元の対象と一致している。

### 概念の共通定義

共通定義は重要な要素を網羅するためではなく、反復する同じモノ・コトを一貫して表現するためのものである。

- 図解全体で複数箇所に登場する同じモノ・コトはすべて共通定義され、それ以外は共通定義に含まれていない。複数の図解に共通する場合と、1枚の図解の複数箇所に登場する場合の両方を含む。
- 出現箇所は、原文の言及回数ではなく図解内で数えられている。
- 共通定義には一貫した名称、基本図形、表示ラベル、固有の絵またはアイコンがある。各出現箇所の表現は、その定義に適合している。
- 異なる共通概念には互いに重複しない絵・アイコンが定義されている。
- 1箇所にしか登場しないモノ・コトは、重要度によらず共通定義されていない。計画では構図内で識別できれば十分であり、局所要素の別表や個別の表現定義、絵・アイコンは必要ない。
- 共通定義されていない局所要素に任意で絵・アイコンを付ける場合、その表現は共通概念の絵・アイコンと重複していない。局所要素同士では同じ絵・アイコンを使用できる。
- 反復する概念がなければ共通定義は空であり、定義を埋めるための要素や出現箇所が追加されていない。

たとえば、1枚の前後比較で同じ利用者とサーバーがそれぞれ前後に現れ、キューが変更後だけに現れる場合、共通定義は利用者とサーバーだけである。キューは変更後の構図内で識別できればよい。

### 構図計画

以下は図解の構図計画に適用する品質基準である。計画の表現形式、提出形式、章立ては定めない。

- 構図から、主題を担う要素の位置・占有サイズ・該当する向きや接続関係を判別できる。
- 共通定義された概念と各出現箇所の対応が識別でき、1箇所だけの要素も名称で識別できる。
- 線の接続と整列が明瞭で、意図しない接続や分断に見える箇所がない。
- 構図と視覚表現の指定が区別でき、色や画風の説明が配置・接続の読解を妨げていない。
- 構図は、対象のキャンバスと適用される視覚表現の制約内で実現可能である。図解の主題と主要な関係は、計画と実装で一致している。
- すべての構図計画が、ほかの Context を持たない第三者サブエージェントによる理解可能性評価に合格している。すなわち、
  - 各構図計画には、現在の図が伝えるべき主題・主要な関係・変化・結果を明示した比較基準が、理解可能性評価より前に記録されている。複数箇所を一図にまとめる場合、比較基準には各対象箇所についてこれらの内容と、対象箇所間の意味上の関係が記録されている。
  - 各構図計画には、第三者が盲検で読み取った主題・関係・変化・結果、それらと比較基準との比較、重大な問題の有無、最終判定からなる評価記録が対応している。
  - 第三者が盲検で読み取った内容と比較基準を比較した結果、現在の図が伝えるべき主題・主要な関係・変化・結果について、重大な誤解・欠落・意味の逆転がない。
- 先行文章と合わせれば理解できる内容は、構図内で重複して説明されていなくてもよい。ただし、現在の図が新たに伝える主題・関係・変化・結果は、先行文章だけへ依存せず構図から読み取れる。

## 理解可能性の評価手続き

この手続きは、構図計画に関する上記の不変条件だけを確認するために独立して実行する。図解作業全体の開始順序、画像生成、文書編集、完了報告は規定しない。

1. 評価対象の構図計画を用意し、比較基準を、現在の図が伝えるべき主題・主要な関係・変化・結果として評価前に確定し、その計画へ記録する。複数箇所を一図にまとめる場合、各対象箇所についてこれらの内容を記録し、さらに対象箇所間の意味上の関係を含める。
2. 同じ文書の入力文章から、その構図が表現する最初の対象箇所より前にある文章だけを先行文章として取り出す。対象箇所そのものと、それ以後の文章は含めない。複数箇所を一図にまとめる場合も、最も前にある対象箇所の開始位置を境界にする。
3. 新しいサブエージェントを、ほかの会話履歴や適用 Skill を継承しない独立コンテキストで起動する。
4. 最初の入力では、対象の構図計画から対象箇所、比較基準、既存の評価記録を伏せた構図表現と、手順2で確定した先行文章だけをサブエージェントへ渡す。先行文章がない場合は構図表現だけを渡す。
5. この盲検段階では、現在または後続の対象文章、手順1の比較基準、適用中の Skill、概念一覧などの別資料、作成者による追加説明、期待する解釈を渡さない。
6. サブエージェントに、構図表現と先行文章から読み取った主題、概念間の関係、変化、結果を出力させ、この出力を確定させる。
7. 出力の確定後、同じサブエージェントへ手順1の比較基準だけを追加で渡す。手順6の出力と比較基準を比較させ、主題・主要な関係・変化・結果について、重大な誤解・欠落・意味の逆転があるかを判定させる。比較基準に含まれない細部の差は判定対象にしない。
8. 重大な問題がなければ合格とし、手順6の盲検出力、比較結果、重大な問題の有無、最終判定を構図計画に対応づけて記録する。
9. 不合格なら構図を修正し、以前の評価内容を持たない新しいサブエージェントで同じ手続きを再実行する。
