# 散らかった考えを整理する

## 目的

入力に散在する考えを削ったり補ったりせず、各箇条書き群の概要と、全体の分類および各話題の論理的な関係を一目で追える状態にする。

## 成果

入力文書を再構成した箇条書きMarkdownを生成する。成果は次の条件をすべて満たすこと。

- 日本語は句点「。」、英語はピリオド「.」だけを境界に分けた、意味を持つすべての文を箇条書きに含める。読点「、」とカンマ「,」では分けない。
- 入力の各文をちょうど1回だけ箇条書きに配置し、省略、重複、要約、統合、意味の追加、意味の変更をしない。区切りに使った句点またはピリオドと周辺の空白だけは、箇条書きとして自然になるよう整えてよい。後述の要約文は、この一対一対応の対象に含めない。
- 文書全体を最もうまく分類できる共通の軸を1〜3個だけ使用する。軸の各値をグループとして表し、同じ見出し階層では同じ軸で一貫して分類する。
- 最上位グループを `##`、下位グループを `###`、`####` で表す。グループは最大3階層とし、`#` または `#####` 以下の見出しを使わない。
- 各末端グループでは、並列関係にある話題ごとに箇条書き群を作り、異なる話題の間だけを `---` で区切る。
- `---` で区切られる各箇条書き群の直前に、その箇条書き群全体を要約する1文を、箇条書きにせず置く。要約文は入力から読み取れる内容だけで構成し、新しい主張や結論を加えない。見出しだけに対する要約文は置かない。
- 一つの箇条書き群では、抽象から具体、概要から詳細、主張から理由・根拠・例など、その話題に最も自然な縦の関係で文を並べる。直接の従属関係がある場合だけ箇条書きをネストする。
- 整理結果だけを出力し、指定された各箇条書き群の要約文以外の前置き、分類軸の解説、作業メモ、入力にない結論を加えない。
- 整理後にユーザーが任意の箇条書き群内または文書末尾へ文章を追記していても、再実行時にはその追記を既存の入力文とともに漏れなく再分類する。
- 入力がファイルの場合、ユーザーが別の出力ファイルを明示しない限り、そのファイルをin-placeで更新する。別ファイルを明示した場合は指定先へ書き、会話に直接入力された文章の場合は整理結果を応答として返す。

## 整理方法

1. 初回実行では入力全体からユーザーが書いた文章を抽出する。再実行では、既存の整理結果から見出し、各箇条書き群の直前にある要約文、区切り線、箇条書き記号などの構造だけを除外し、以前からある入力文とユーザーが後から追記した文章をすべて抽出する。追記位置や既存グループへの所属を分類情報として扱わない。
2. 抽出した文章を、日本語は句点「。」、英語はピリオド「.」だけを境界として非空な文に分解する。読点「、」とカンマ「,」では分けない。各文を最後まで追跡できる一時的な識別子を付ける。
3. 初回・再実行ともに、すべての文をネストや見出しのない一段の箇条書きへ変換する。既存の見出し、要約文、区切り、ネスト、所属グループをこのフラットな入力へ含めない。
4. 自分と同じモデルを使う新しいsubagentを起動し、フラットな箇条書きとこのSkillの成果条件だけを渡して整理結果を生成させる。モデルのoverrideを指定しない。元の文書や既存のグルーピングをsubagentへ渡さず、親エージェント側で先に分類しない。
5. 一時的な識別子の一覧とsubagentの出力を照合し、入力のすべての文が一対一で対応することを確認してから識別子を外す。欠落、重複、変更があれば、フラットな箇条書きと成果条件だけを使ってsubagentに修正させる。
6. ファイル入力では、ユーザーが別ファイルを明示した場合だけ指定先へ書き、それ以外はGitで履歴を復元できる前提で入力ファイルをin-place更新する。会話に直接入力された文章では、整理結果を応答として返す。

出力形は次の骨格に従う。必要な見出し階層だけを使用する。

```markdown
## 分類値

### 分類値

箇条書き群全体を要約する1文。

- 抽象的な文または話題の主張
  - 具体的な文、理由、根拠、または例

---

別の箇条書き群全体を要約する1文。

- 並列する別の話題の文
  - その詳細
```
